# 更新日時差分ダンプ方式設計

作成日: 2026-07-28
状態: PoC前の候補設計

## 1. 位置づけ

更新日時条件による差分 Data Pump は、更新日時が信頼でき、差分量が小さいテーブルの候補とする。全テーブルへの既定方式にはしない。

この方式だけでは物理 DELETE と、重複抽出窓を超える遅延コミットを完全には捕捉できない。欠落ゼロが必須の表は、LogMinerによる変更キー照合または最終全件照合を組み合わせる。

## 2. 採用前提

以下をすべてテーブル単位で確認する。

- INSERT と UPDATE のたびに更新日時が設定される
- DBトリガー、共通DAO等の設定主体が特定できる
- 列型、秒以下精度、タイムゾーン、NULL可否が明確
- バックデート、手動補正、バルクロード時の例外処理がないか把握済み
- 最大トランザクション時間と遅延コミット分布を計測済み
- 物理 DELETE の有無と取得経路が決定済み
- 更新日時索引または有効なパーティションがある、またはフルスキャンを許容できる
- LOB搬送量を含む実測が許容範囲

一つでも不明なら方式決定を保留する。

## 3. 境界

抽出対象は原則として次の形にする。

```text
snapshot: AS OF SCN S_upper
time range: [T_prev - overlap, T_upper)
```

概念的な Data Pump 条件:

```text
FLASHBACK_SCN=S_upper
QUERY=<table>:"WHERE UPDATED_AT >= :from_with_overlap
                     AND UPDATED_AT <  :to_timestamp"
```

実際のパラメータファイルではバインド変数ではなく、型とタイムゾーンを明示したリテラルを生成する。

`overlap` は安全性を高めるが、欠落ゼロの証明にはならない。更新日時が `T_prev - overlap` より古いまま、`S_upper` 後にコミットされたトランザクションは次回以降に漏れ得る。したがって次のどちらかを必須とする。

- 最大トランザクション時間を実測し、その上限を超える重複窓と監視を持つ
- LogMinerのコミットSCN範囲から変更キーを照合し、更新日時抽出との差分を補完する

## 4. DELETEと主キー更新

物理 DELETE は LogMiner の `UNDO_VALUE` から旧主キーを取得する。主キー更新は旧キーDELETEと新キーUPSERTに分解する。

```text
INSERT / UPDATE:
  更新日時差分で行イメージを取得

DELETE:
  LogMinerで旧主キーを取得

PK UPDATE:
  旧主キーDELETE + 新主キーUPSERT
```

論理削除だけの表でも、論理削除列が必ず更新日時を更新することを確認する。

## 5. Export方式

### 5.1 直接QUERY

元表へ `expdp QUERY` を指定する。追加表が不要で運用は単純だが、Oracle仕様上 External Table 経路になる。通常SELECTの実行計画だけで判断せず、Data Pumpログの Access Method、経過時間、I/O、業務影響を測る。

### 5.2 固定差分表

元表を `AS OF SCN S_upper` で読み、バッチ専用の固定差分表へ物理化してからExportする。再Export、監査、重複圧縮には有利だが、元表読込み、差分表書込み、差分表再読込みの追加I/Oが発生する。

次をPoCで比較する。

- バッチ専用物理表
- 再利用表のTRUNCATE方式
- バッチ単位パーティション
- 小さい共有表にQUERYを指定

## 6. 適用と冪等性

- UPSERTは主キーで冪等に適用する
- DELETEは対象行0件を異常とするか、再実行時の正常状態とするかを区別する
- 同一バッチの再Import・再適用で最終結果が変わらないことを試験する
- STAGING適用、2.0変換、検証のチェックポイントを分離する

## 7. 不採用条件

次の場合は更新日時方式を第一候補にしない。

- 更新日時設定の例外経路が残る
- 最大トランザクション時間を把握できない
- 物理DELETEを補完できない
- 差分率が高くフルスキャンが継続的に発生する
- 巨大LOBの再搬送が支配的
- 主キー更新や特殊型を安全に処理できない
- 本番相当PoCでソース業務影響が許容値を超える

## 8. 必要成果物

- テーブル別更新日時信頼性台帳
- 更新日時・パーティション・索引棚卸しSQL
- 直接QUERY用パラメータ生成仕様
- 固定差分表のDDL・作成・削除手順
- DELETE補完仕様
- 遅延コミット監視SQL
- 再実行判断表
- 正確性・性能PoC結果
